## 1. ¿Cuál es la diferencia principal entre una prueba unitaria y una prueba de integración E2E?
- Prueba unitaria:Valida de manera aislada una pieza mínima de código (una función o clase), asegurando que su lógica interna funciona correctamente

- Prueba de integración E2E (End-to-End):Valida el sistema completo desde la perspectiva del usuario, verificando que todos los módulos interactúan correctamente entre sí y que los flujos de negocio funcionan de extremo a extremo

## 2. En Scrum ¿Cuál es el propósito de la Sprint Retrospective y porque es crucial para la mejora continua del equipo?
La Sprint Retrospective busca que el equipo inspeccione cómo trabajó durante el sprint, identifique áreas de mejora y acuerde acciones concretas para el siguiente
## 3. Explique la diferencia entre una Épica, una Feature y una historia de Usuario. Proporcione un ejemplo de cada una si tenemos un sistema de streaming de video como lo es Netflix
- Épica: Gran iniciativa o funcionalidad que se descompone en varias features/(EJEMPLO):Permitir que los usuarios disfruten de contenido en cualquier dispositivo
- Feature: Una capacidad específica dentro de una épica./(EJEMPLO):Reproducción de video en dispositivos móviles
- Historia de Usuario: Requerimiento pequeño y detallado, centrado en el usuario./(EJEMPLO):Como usuario, quiero pausar y reanudar el video desde mi celular, para continuar viendo donde lo dejé
## 4. ¿Qué es una cobertura de Código (code coverage) y porque una cobertura del 100% no garantiza necesariamente que el software esté libre de errores?
- Es una métrica que indica qué porcentaje del código fue ejecutado durante las pruebas.

- Limitación: Un 100% de cobertura solo asegura que cada línea fue ejecutada, pero no garantiza que las salidas sean correctas ni que se hayan probado todos los casos límite.
## 5. Describa que es un Diagrama de Casos de Uso y que elementos lo componen. ¿Para qué sirve en la fase de análisis de requerimientos?
Un diagrama UML que representa las interacciones entre actores (usuarios o sistemas externos) y el sistema en términos de casos de uso (funcionalidades)

Elementos principales:

- Actores

- Casos de uso

- Relaciones (inclusión, extensión, generalización)

- El sistema (límites)
En análisis de requerimientos sirve para entender y comunicar qué funcionalidades espera el usuario del sistema de forma clara y visual.
## 6. ¿Cuál es la diferencia entre el uso de Junit y Jacoco en un proyecto, y como complementa SonarQube este proceso en términos de calidad de software?

- JUnit: Framework para escribir y ejecutar pruebas unitarias en Java

- JaCoCo: Herramienta para medir cobertura de código durante la ejecución de pruebas

- SonarQube: Plataforma de análisis de calidad que integra resultados de pruebas y cobertura, detecta code smells, vulnerabilidades y deuda técnica

#### Cómo se complementan:

- JUnit prueba el código

- JaCoCo mide qué tanto de ese código fue cubierto

- SonarQube da una visión integral de calidad y mantenibilidad
## 7. ¿Qué ventajas tiene el uso de Planning Poker frente a otros métodos de estimación tradicional y como ayuda a mejorar la transparencia y compromiso del equipo?

- Involucra a todo el equipo en la estimación

- Reduce el sesgo de una sola opinión (se vota en simultáneo)

- Fomenta la discusión cuando hay diferencias de estimación

- Aumenta la transparencia y compromiso, ya que el resultado surge del consenso del equipo
